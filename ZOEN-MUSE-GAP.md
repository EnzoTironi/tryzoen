# Building Muse capabilities on Zoen

Assessment: 2026-09-27. Target: all observable capabilities of the original Muse, as requested.

## Recommendation

Continue building on **Zoen**. Its existing agent runtime, browser worker, memory, schedules, tool publishing, messaging and workspace controls are a stronger starting point for this project than replacing them with OpenMuse. Use OpenMuse as a product reference and consider individual components only when they solve a specific missing capability.

This supersedes the earlier recommendation made before the Zoen repository was supplied. It is an architectural recommendation based on inspected code, not a claim of complete Muse parity or equivalent model performance.

## Code evidence for the important distinctions

- **The agent core already exists.** [`agent/agent.ts`](https://github.com/EnzoTironi/tryzoen/blob/e12f4962e908c8f2fcb4f3c41282fa1c0837f095/agent/agent.ts) selects models dynamically and uses the PostgreSQL workflow world. [`eve-native.integration.ts`](https://github.com/EnzoTironi/tryzoen/blob/e12f4962e908c8f2fcb4f3c41282fa1c0837f095/tests/runtime/eve-native.integration.ts) exercises duplicate deliveries, restart, memory updates and pending approvals. Preserve Eve as the owner of orchestration.
- **Browser control is implemented.** [`computer_action.ts`](https://github.com/EnzoTironi/tryzoen/blob/e12f4962e908c8f2fcb4f3c41282fa1c0837f095/server/tools/browser/computer_action.ts) sends clicks, typing, scrolling and screenshots to Kernel. [`manage_browsers.ts`](https://github.com/EnzoTironi/tryzoen/blob/e12f4962e908c8f2fcb4f3c41282fa1c0837f095/server/tools/browser/manage_browsers.ts) manages persistent profiles. These operate remote browser sessions, not apps on the user's Mac.
- **Memory and scheduling are more than UI placeholders.** [`learned.ts`](https://github.com/EnzoTironi/tryzoen/blob/e12f4962e908c8f2fcb4f3c41282fa1c0837f095/agent/memory/learned.ts), [`workstreams.ts`](https://github.com/EnzoTironi/tryzoen/blob/e12f4962e908c8f2fcb4f3c41282fa1c0837f095/agent/memory/workstreams.ts) and [`dynamic.ts`](https://github.com/EnzoTironi/tryzoen/blob/e12f4962e908c8f2fcb4f3c41282fa1c0837f095/agent/schedules/dynamic.ts) contain scoped recall and actual scheduled worker dispatch. Saving a workstream does not itself schedule execution.
- **Tool creation has an existing lifecycle.** [`customer-tools.ts`](https://github.com/EnzoTironi/tryzoen/blob/e12f4962e908c8f2fcb4f3c41282fa1c0837f095/server/tools/customer-tools.ts) resolves published definitions and executes bounded customer code or approved remote operations. Its [integration test](https://github.com/EnzoTironi/tryzoen/blob/e12f4962e908c8f2fcb4f3c41282fa1c0837f095/tests/runtime/customer-tools.integration.ts) covers publication, discovery, revocation and rollback. This is valuable reuse, but not unrestricted self-modification.
- **Shell access is deliberately absent.** [`agent/tools/bash.ts`](https://github.com/EnzoTironi/tryzoen/blob/e12f4962e908c8f2fcb4f3c41282fa1c0837f095/agent/tools/bash.ts) and the browser subagent's equivalent return `disableTool()`. [`agent/sandbox.ts`](https://github.com/EnzoTironi/tryzoen/blob/e12f4962e908c8f2fcb4f3c41282fa1c0837f095/agent/sandbox.ts) supplies a virtual filesystem with automatic installation disabled. Merely enabling bash would not provide the missing machine lifecycle, persistence and permissions.
- **Channel multimodality is an explicit gap.** [`requireChannelModelInput`](https://github.com/EnzoTironi/tryzoen/blob/e12f4962e908c8f2fcb4f3c41282fa1c0837f095/server/channels/media/policy.ts#L134) rejects image/PDF input. The [media contract](https://github.com/EnzoTironi/tryzoen/blob/e12f4962e908c8f2fcb4f3c41282fa1c0837f095/server/channels/media/README.md) documents optional audio transcription. This distinction prevents mistaking saved attachments for model understanding.
- **Connector breadth remains conditional.** [`agent/connections/treg.ts`](https://github.com/EnzoTironi/tryzoen/blob/e12f4962e908c8f2fcb4f3c41282fa1c0837f095/agent/connections/treg.ts) separates catalog queries from approved calls. Direct Google tools are registered in the [capability catalog](https://github.com/EnzoTironi/tryzoen/blob/e12f4962e908c8f2fcb4f3c41282fa1c0837f095/server/tools/catalog.ts). Neither a provider's name nor endpoint count establishes parity with a Muse connector.

## Where OpenMuse fits now

OpenMuse remains useful for comparing the presentation of goals, ideas, approvals, task progress and browser results. Its mobile UI or PDF workflow may provide useful implementation references after evaluating fit. Its optional Linux computer is also worth comparing with Zoen's missing general execution environment.

Replacing Zoen's backend with OpenMuse would duplicate existing work in memory, scheduling, custom tools, channels and authorization, while introducing another conversation-persistence dependency. The original recommendation to start there no longer applies. Any selective reuse should fit Zoen's existing owners rather than add a second agent runtime.

## Recommended implementation order

1. **Establish current functional coverage.** Turn this inventory into end-to-end scenarios against the intended Zoen installation: remember/correct a preference; resume a task after restart; use an authenticated website; execute and report a scheduled task; publish and reuse a custom tool. Record actual destination state for each result.
2. **Complete the agent's execution environments.** Add the persistent general computer and a native Mac companion. Keep remote browser actions, cloud shell execution and local Mac control distinct in implementation and permissions.
3. **Complete multimodal and document workflows.** Enable verified channel image/PDF input, richer document creation, image generation and voice output where the chosen providers support them.
4. **Close proactive behavior and connector gaps.** Extend workstreams/schedules into the intended goals and ideas experience; qualify the original Muse connector inventory one operation at a time.
5. **Complete device experience.** Add native clients, notifications and continuity as required by full parity. Messaging channels already provide a useful existing access path.

This sequence retains the full Muse target. No percentage or completion date is assigned: the missing native and provider-dependent work needs its own bounded implementation plan. This assessment changed local planning documents only; it did not modify, deploy or send messages through Zoen.
